# AI Usage

This project was built with mindful use of an AI assistant (Claude, by Anthropic),
as permitted by the assessment brief. This document records where it was used,
what I did with its output, and what I wrote myself.

## Principles I followed

- AI was used for guidance, drafts and troubleshooting, not to generate the whole application.
- I reviewed every piece of AI-assisted output before using it, and I can explain it.
- Architecture decisions, application code, tests and documentation are my own work,
  except where listed below.

## Not Generated by AI

The following work reflects my own implementation and technical decisions:

- Selected the technology stack and organized the implementation approach based on the assessment requirements.
- Reviewed and made the final decisions on the database schema, relationships, constraints, indexes, and seed-data strategy.
- Implemented and refined the application architecture and backend features, reviewing how the Domain, Application, Infrastructure, and WebAPI layers interact.
- Made implementation decisions regarding authentication, authorization, validation, error handling, and dependency injection.
- Reviewed AI-assisted changes, checked their consistency with the existing codebase, and decided which changes to keep or modify.
- Verified the application through builds and tests, investigated failures, and assessed the remaining gaps against the assessment requirements.

## How I verified AI output

- Original project verification is recorded above; for this follow-up, Codex ran `dotnet build Monitoring.slnx` and the .NET test suite (27 passed), plus `npm run build` (passed).
- `npm test` was run and reported that no client test files are present.
- Checked advisories and package versions against their official sources.
- The new HTTP integration tests use ASP.NET Core TestServer and EF Core InMemory; they do not start SQL Server or Hangfire.
